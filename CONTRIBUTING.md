# Как контрибьютить

1. Для заметных изменений — сначала issue, потом PR: обсудим до того,
   как ты потратишь вечер.
2. Ветка от `master`, PR в `master`. CI (typecheck + тесты + сборка)
   должен быть зелёным.
3. Логика ядра (`src/logic`) меняется только вместе с vitest-тестами
   на граничные случаи.
4. Прочти [CLAUDE.md](CLAUDE.md) — там инварианты, которые нельзя ломать
   (append-only логи, детерминизм неба, «одно ядро — все головы»).
   Файл читают и люди, и агенты.
5. Язык UI-текстов и комментариев — русский; технические термины в оригинале.
6. Формат `store.json` — публичный контракт: несовместимое изменение
   обязано нести миграцию.

## Как выпускается релиз

Для мейнтейнера. Push в `master` сам выкатывает веб на сервер проекта
(`deploy.yml`), тег `v*` собирает и публикует Docker-образ (`release.yml`).

1. В `CHANGELOG.md` под `## [Unreleased]` появляется раздел
   `## [X.Y.Z] — ГГГГ-ММ-ДД`: вводка в одну-две строки, блок
   `### Обновление с <прошлой версии>` (том, миграции, что перезагрузить,
   возможен ли откат), дальше накопленные «Добавлено / Изменено / Исправлено».
   Пустой `[Unreleased]` остаётся сверху.
2. Версия: `npm version X.Y.Z --no-git-tag-version` — правит `package.json` и
   `package-lock.json`, тег не ставит.
3. `npm run typecheck` и `npm test`, затем коммит
   `docs: X.Y.Z — CHANGELOG и версия` и push в `master`.
4. Аннотированный тег на этом коммите: `git tag -a vX.Y.Z -m "Stargaze X.Y.Z — …"`,
   затем `git push origin vX.Y.Z`.
5. Страница релиза: `gh release create vX.Y.Z --title "Stargaze X.Y.Z"` с
   текстом раздела из `CHANGELOG.md`; ссылки на файлы репозитория — абсолютные,
   на тег. Скриншоты и ролики снимаются на демо-мире, не на чьих-то данных.
6. Если менялся состав модулей — пересобрать карту кода:
   `node docs/codemap/build.mjs` ([docs/codemap](docs/codemap/README.md)).
