# Установка Stargaze

Для того, кто ставит Stargaze — человека или его агента. Прочти до
команд: путь установки зависит от одного ответа.

## Один вопрос: где живёт твой агент?

Stargaze — небо, квесты и экономика. Гейм-мастер — твой AI-агент: он
ходит в те же данные через CLI или HTTP API. Поэтому Stargaze ставится
туда, где живёт агент.

| Где агент | Путь | Что получишь |
|---|---|---|
| На ноутбуке (Claude Code, Codex, свой скрипт) | [Локально](#локально) | Работает, пока ноутбук включён; небо — только на нём |
| На сервере 24/7 (Hermes, OpenClaw, своё на VPS) | [VPS](#vps) | Небо с любого устройства по HTTPS; агент ведёт игру без тебя |
| Агента пока нет | [Локально](#локально) | Ведёшь руками, агента подключишь потом; переезд — один файл |

Так стоит у автора: агент на VPS, Stargaze рядом с ним. Локальный путь
технически ничем не хуже — та же сборка, тот же формат данных. Разница
в том, что сервер не выключается и доступен с телефона.

## Локально

Нужен [Node.js](https://nodejs.org) 22.12 или новее.

```bash
git clone https://github.com/ilia-pluzhnikov/stargaze.git
cd stargaze
npm install
npm run serve        # → http://localhost:8643
```

Первый запуск создаёт демо-мир в `~/.stargaze/store.json`. Это все
данные: бэкап и перенос — копирование файла.

Агент ходит через CLI. Путь к store по умолчанию знает только `serve`,
остальным командам он нужен явно — через env или `--store <путь>`:

```bash
export STARGAZE_STORE="$HOME/.stargaze/store.json"
node dist-node/cli.js status          # сводка мира
node dist-node/cli.js                 # справка по командам
```

`serve` и CLI работают с одним файлом одновременно: сервер не держит
store в памяти, каждая запись идёт через лок и атомарную замену файла.

Проверка: `curl http://localhost:8643/api/health` → `{"ok":true}`.

С телефона локальную установку не видно. Туннель (cloudflared, ngrok)
покажет небо, но в текущей версии веб через туннель — только для
чтения: `serve` принимает действия лишь с Origin `localhost`. Нужен
телефон — ставь на VPS.

Docker вместо npm:

```bash
docker run -d --name stargaze -p 127.0.0.1:8643:8643 -v stargaze-data:/data ghcr.io/ilia-pluzhnikov/stargaze:latest
docker exec stargaze node cli.js status
```

В образе путь к store уже задан (`STARGAZE_STORE=/data/store.json`).
Образ собран под `linux/amd64`: на Apple Silicon пойдёт через
эмуляцию, на ARM-сервере не запустится — там путь через npm.

## VPS

Рецепт — [DEPLOY.md](DEPLOY.md): контейнер Stargaze плюс reverse proxy
с HTTPS и паролем. В примере прокси — Caddy, но это пример, не
требование: чем его заменить и что прокси обязан делать — там же.

Агент на том же сервере ходит мимо прокси:

```bash
docker exec stargaze node cli.js status
docker exec stargaze node cli.js propose-quest --title "…" --type short --xp 40 --note "зачем"
```

или `POST /api/action` изнутри docker-сети — без пароля и без Origin.

## Правила для агента-установщика

- Порт наружу — только через прокси. `-p 8643:8643` без прокси
  открывает запись в store любому, кто нашёл адрес: у API нет своей
  авторизации.
- Один store. Не заводи второй «для проверки» рядом с рабочим — агент
  и веб должны смотреть в один файл.
- Перед обновлением — [CHANGELOG](CHANGELOG.md). Формат store
  версионирован: старые файлы мигрируются при чтении, рядом остаётся
  копия прежней версии.
- Бэкап = копия `store.json` (для Docker-тома — команда в DEPLOY.md).
- Переезд между путями: экспорт на старом месте, импорт на новом —
  кнопка «Данные» в вебе или `cli.js export <файл>` / `cli.js import
  <файл>`. Импорт заменяет всё состояние целиком.
