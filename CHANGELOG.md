# Changelog

Версии — [semver](https://semver.org/lang/ru/). Формат store.json —
публичный контракт: несовместимое изменение формата обязано нести миграцию.

## [Unreleased]

## [0.4.0] — 2026-10-31

HTTP API становится полноценным интерфейсом гейм-мастера без `docker exec`;
игровой пояс настраивается.

### Обновление с 0.3.1

- Том со `store.json` подходит как есть: формат v4 тот же, миграций нет.
- Игровой пояс не UTC+7 — поставь его сразу после обновления:
  `POST /api/action` с `{"type":"setGameTz","offsetMin":300}` (минуты от UTC,
  кратно 15) или `cli.js tz +05:00`. Переменной окружения для пояса нет — он
  хранится в store.
- Обновляй образ целиком и перезагрузи открытые вкладки: веб, CLI и сервер
  0.3.1 о поясе не знают и считают день по UTC+7.
- Откат на 0.3.1 возможен, но поставленный пояс старая версия не увидит.
- Агенту: `POST /api/action` теперь отвечает 400 на неверную форму payload и
  422 с причиной на отказ сдачи квеста. Читать состояние можно через
  `GET /api/status`, `/api/quests` и другие срезы — их список в
  [API.md](API.md). Конфиг прокси менять не нужно.

### Добавлено

- **Чтение через HTTP API:** `GET /api/status`, `/api/wallet`, `/api/quests`
  (`?filter=today|proposed|all`), `/api/quests/<id>`, `/api/skills`,
  `/api/ranks?skill=`, `/api/stars`, `/api/stats?weeks=`, `/api/wishlist`.
  Ответ — тот же JSON, что `cli.js <команда> --json`: агенту больше не нужно
  копировать `cli.js` из образа и гонять его по снимку store.
- **`API.md`** — справочник HTTP API: маршруты, поля действий
  (`questId`/`skillId`/`itemId`, а не `id`), коды ответов.
- **Игровой пояс.** Игровые сутки можно перевести на свой пояс:
  `stargaze tz +05:00` (отрицательный — `stargaze tz -- -03:30`), агенту —
  действие `setGameTz` в `POST /api/action`. Пояс хранится в store и один для
  веба, CLI и API; `stargaze tz` без аргумента показывает текущий, в вебе он
  виден в «Данных». По умолчанию, как и раньше, UTC+7. Уже записанные дни
  отметок и платежей при смене пояса не пересчитываются; летнее время не
  поддерживается.
- **`POST /api/action` говорит, записалось ли действие:** заголовок
  `Stargaze-Applied: 1` или `0`. Перечитывать store после каждой записи не нужно.

### Изменено

- `POST /api/action`: payload неверной формы (нет поля, не тот тип, `id`
  вместо `questId`) — 400 с причиной, а не тихий 200. Payload без `ts` теперь
  тоже 400, а не 422.
- `POST /api/action`: сдача квеста без итога, с незакрытыми пунктами DoD
  (список в `dod`), отметка привычки на ещё не наступивший день и сдача
  контракта со сроком с нечитаемым `ts` — 422 с причиной вместо тихого 200.
- `POST /api/action`: `null` в необязательном поле (`result`, `force`,
  `evidence`, `opId`) — то же, что поле не прислать.
- Формат store: новое необязательное поле `tzOffsetMin`. Версия формата прежняя
  (v4), миграции нет. Версии до 0.3.1 включительно такой файл откроют, но день
  будут считать по UTC+7 — обновляй веб, CLI и сервер вместе.

### Исправлено

- Объект из `stargaze quest <id> --json` можно отправить обратно в
  `updateQuest` как есть: вычисляемые `children` и `progress` больше не оседают
  в store и не показывают устаревший прогресс в `/api/store`. То же для навыков,
  звёзд и позиций витрины — лишние поля отбрасываются, а уже осевшие уходят
  при следующей правке сущности.
- `completeQuest` с `result` без строкового `summary` через API давал 500,
  теперь 422.
- `updateSkill` больше не меняет `archived` и `createdAt`: `archived: true`
  прятал навык мимо проверки активных контрактов в `archiveSkill`. Архив —
  только `archiveSkill`.
- `ts` с пробелом вместо `T` (`2026-10-30 23:30:00Z`, так печатает Python)
  читается как момент; раньше время и зона отбрасывались и день мог уехать на
  сутки.

## [0.3.1] — 2026-10-30

Веб при сбое связи с сервером: не молчит и не теряет правки. Формат store,
HTTP API и CLI не менялись.

### Обновление с 0.3.0

- Том со `store.json` подходит как есть: формат v4 тот же, миграций нет,
  откат на 0.3.0 безопасен.
- Агенту ничего менять не нужно: `/api/store`, `/api/action` и `cli.js` те же.
  Конфиг прокси тоже менять не нужно.
- Баннер «нет связи» и очередь правок без связи работают в браузере, который
  хотя бы раз подключился к серверу уже на 0.3.1 (отметка
  `stargaze.server-seen` в localStorage). До первого подключения после
  обновления — как в 0.3.0.
- В серверном режиме веб теперь держит в localStorage (`stargaze.v4`) копию
  последнего канона. Если там лежала старая локальная сессия, которую хочется
  сохранить, выгрузи её до обновления: «Данные» → экспорт.

### Исправлено

- **Сбой связи больше не молчит и не теряет правки.** Если `/api/store` не
  ответил (рестарт контейнера, ошибка прокси, медленная сеть), вкладка
  показывала мир из давней локальной сессии, причина пряталась в подсказке
  бейджа «локальный режим», а правки из такой вкладки при возврате связи
  затирались. Теперь на экране копия последнего канона из этого браузера,
  баннер «Нет связи с сервером… последняя синхронизация <время>», а правки
  копятся в очереди и уходят на сервер, когда связь вернётся. Импорт и сброс
  без связи не выполняются — UI так и сообщает.
- Страница, открытая по адресу с логином (`https://user:pass@host/`),
  навсегда оставалась в локальном режиме. Запросы к API теперь идут от
  `location.origin`.
- Импорт и «Сброс» больше не встают в очередь: отложенный импорт мог
  доиграться спустя дни и затереть всё, что сервер накопил после, в том числе
  правки агента. Теперь — сразу или отказ «Сервер недоступен — импорт не
  выполнен».
- В шапке — счётчик «в очереди: N», пока есть неотправленные действия.

### Изменено

- Центр обзорного неба закреплён за навыком с id `s_treasury`, а не за
  названием «Казна…»: навык, названный «Казна», теперь встаёт по общей
  раскладке. Остальные позиции не меняются.

### Добавлено

- **Вход устройства без пароля** в примере Caddy (`deploy/Caddyfile.example`):
  ссылка `/?device=<токен>` ставит cookie на год. Нужна для телевизора,
  который забывает basic auth при каждом перезапуске. Включается переменной
  `STARGAZE_DEVICE_TOKEN` (не короче 32 символов); без неё конфиг ведёт себя
  как раньше. Токен из ссылки в лог не пишется. Касается только примера
  Caddy: образ и другие прокси не затронуты. См. DEPLOY.md.

### Документация

- INSTALL.md — куда ставить: решает место, где живёт агент.
- GUIDE.md — путеводитель: стратсессия первой, неделя с гейм-мастером.
- DEPLOY.md — вход без пароля для устройств; что обязан делать прокси, если
  вместо Caddy nginx или другой.

## [0.3.0] — 2026-09-22

Привычки без расписания и стриков, история неба; формат store v4.

### Breaking

- **Формат store v4.** Файлы и экспорт v3 мигрируются автоматически при чтении
  (сервер, CLI, импорт в вебе и через API). Перед первой записью рядом с файлом
  кладётся страховочная копия `store.json.v3.bak`. Квест с полем `daysOfWeek`
  больше не проходит валидацию (API отвечает 422).
- **CLI:** опция `--days` у `add-quest`/`propose-quest` удалена (код 2 с
  пояснением). `status --json`: поле `skills[].streak` удалено,
  `today: { due, done }` → `today: { due, habitsDone }`. `ranks --json`: поле
  `title` удалено.
- Ключ localStorage — `stargaze.v4`; `stargaze.v3` и `questlog.v3` читаются
  вечно и не удаляются.

### Изменено

- Привычку можно отметить (и снять) за любой прошедший день прямо в Хронике.
  XP — за любой день, искры — только за сегодня и вчера. Снятие отметки старше
  вчера — в два клика: искры за неё повторной отметкой не вернуть.
- Расписание по дням недели, стрики и недельные нормы убраны: Хроника
  показывает плотность отметок, без «пропусков». Легенда клеток тоже убрана —
  состояний осталось два, над сеткой одна строка-подсказка.
- Привычки живут только в Хронике (название открывает правку и архив);
  Журнал — только контракты.
- `complete <привычка> --day <будущее>` — отказ с кодом 2.
- Журнал на десктопе: правая панель (персонаж и навыки) остаётся на месте при
  прокрутке списка контрактов; в низком окне прокручивается сама.
- У рангов больше нет названий — только буква D–S и счёт звёзд. Убраны и
  классы светимости («Карлик»…«Гипергигант»), и переименование рангов в
  настройках навыка (вместе с кнопкой «✎ Ранги» в галактике). Формат store не
  менялся: поле `skills[].rankTitles` в прежних файлах не читается и валидации
  не мешает.
- Требование к Node.js записано явно: 22.12 или новее (`engines` в
  `package.json`, строка в README). Фактически оно было таким и в 0.2.0 —
  Vite 7 и бандлы под `node22`; теперь `npm install` на старом Node предупредит
  сразу, а не упадёт невнятно на сборке.
- Workflow `deploy` в форках пропускается: это личный деплой автора, без его
  секретов он падал бы на каждом push в `master`.

### Добавлено

- Имя и аватар персонажа теперь можно сменить: в вебе — клик по имени или
  аватару в шапке либо в карточке Журнала, в CLI — `character [--name "Имя"]
  [--emoji ⚔️]` (без флагов показывает текущего). Раньше действие `setCharacter`
  было доступно только через API. Пустое имя, пустой или слишком длинный
  (больше 16 юнитов) аватар ядро не принимает — тихий no-op, как прочие отказы.
- История неба: кнопка «◷ История» на небе и в галактике открывает полосу
  времени — тащишь ползунок и видишь, какие созвездия и звёзды уже были, какие
  горели, какими были ранги и уровни; засечки отмечают дни зажиганий и взятых
  рангов, ▶ проигрывает рост неба до сегодня. Прошлое — только для просмотра,
  правка доступна на сегодняшней дате. История выводится из нынешних данных
  (даты создания и зажигания, дни `xpLog`), формат store не менялся; это
  приближение: погашенные и удалённые звёзды, прежние названия и родители звёзд
  в прошлом не видны.

## [0.2.0] — 2026-08-26

Первый публичный релиз.

- Небо навыков: галактики, деревья звёзд, ранги D–S, зажигание звёзд руками
  (с evidence), детерминированная раскладка.
- Квесты: повторяющиеся привычки и контракты (short/mid/long) с карточкой —
  описание, «зачем», Definition of Done, ресурсы, итог при сдаче.
- Экономика искр: награда за сдачу вовремя, капание за просрочку, переносы
  дедлайнов с квотой, вишлист (разовые и многоразовые награды, big-награды
  по звезде-якорю), трек накоплений.
- Одно ядро — три головы: веб, CLI, HTTP API.
- `stargaze serve` — локальный запуск одной командой; первый старт создаёт
  демо-мир.
- Docker-образ: `ghcr.io/ilia-pluzhnikov/stargaze`.

В планах: MCP-сервер для агентов, английский интерфейс, npm-пакет.
